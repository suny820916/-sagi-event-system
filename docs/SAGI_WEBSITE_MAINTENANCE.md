# SAGI SPORTS 网站日常维护规范

## 目的

SAGI SPORTS 官网不是一次性项目。

网站需要持续保持：
- 内容准确
- 链接有效
- 手机端正常
- 线上版本与 GitHub 一致
- SAGI 品牌统一
- 不出现过期文案
- 不因新功能破坏旧页面

本规范适用于：
- SAGI SPORTS 首页
- SAGI KIT
- SAGI EVENT
- TORANHE CUP
- SAGI BROADCAST
- ABOUT
- 未来新增公开页面

## 一、每次开始工作的固定检查

Codex 每次进入网站项目，先读取：
- AGENTS.md
- 本文件
- 当前 main 最新提交
- 与本次任务相关的产品文档 / Issue

然后先检查：

1. 首页是否正常打开
2. 主导航是否正常
3. 手机端 390px 是否出现换行、溢出、遮挡
4. 主要页面是否存在 404 / 死链
5. 页面 Logo 是否使用官方 SAGI Logo
6. 是否存在已经过期的产品说明
7. 是否存在“固定8队”“旧版本号”“旧入口”等失效文案
8. 页面按钮是否指向正确产品
9. 本地代码与线上页面是否一致
10. 如无法验证线上，必须明确说明

## 二、日常维护范围

### 1. 内容维护
持续检查：
- 过期文案
- 错别字
- 错误球队名 / 赛事名
- 旧日期
- 旧版本描述
- 已经变化的产品能力
- 未确认信息
- 重复内容

原则：
- 不自行编造赛事结果、冠军、日期
- 未确认内容不得写成正式事实
- 已确认信息优先从结构化数据读取

### 2. 导航维护
主导航保持统一：
- 首页
- 球队装备
- 赛事
- 托朗戈杯
- 直播
- 关于我们

要求：
- 所有主页面导航一致
- 当前页面正确高亮
- 手机端保持单行或合理横向滚动
- 不允许因增加栏目造成两行挤压

### 3. 手机端维护
SAGI 网站以手机端为第一优先。

每次重要修改至少检查：
- 390px
- 430px

重点：
- 导航
- 卡片
- 表格
- 弹窗
- 文件上传
- 打印入口
- 长中文
- 底部固定栏
- iPhone Safari 安全区域

### 4. 链接 / 入口维护
定期检查：
- 主导航
- 首页业务入口
- TORANHE
- EVENT
- KIT
- BROADCAST
- ABOUT
- PDF / 文件
- 分享页

任何 404、错误跳转、旧路径必须修复。

### 5. 品牌一致性
统一使用官方 SAGI FOOTBALL Logo。

保持：
- 黑
- 白
- SAGI 红
- 简洁
- 克制
- 国际足球品牌感

禁止：
- 随意重绘 Logo
- 廉价渐变
- 过度发光
- 无意义动效
- 与品牌不一致的字体/装饰

### 6. 页面性能
避免：
- 巨大图片直接加载
- 不必要 JS
- 重复 CSS
- 无意义第三方依赖
- 首屏阻塞

图片尽量：
- WebP / AVIF
- 合理尺寸
- 懒加载

### 7. 数据与兼容
修改 EVENT / TORANHE 等有数据的页面时：
- 保留旧数据兼容
- 保留备份/恢复
- 不静默丢数据
- schema 变化要有迁移
- 不把大视频/照片直接塞进 Git

### 8. 缓存
更新公共 CSS/JS 后：
- 必要时更新资源版本号
- 避免用户手机继续读取旧缓存

但不要无意义频繁改版本。

### 9. 线上验证
GitHub commit != 线上完成。

每次发布后尽量验证：
- 首页
- 修改页面
- 手机端
- 关键按钮
- 新资源
- 404

如果不能验证线上：
必须写：
“代码已提交，线上部署尚未验证。”

### 10. 安全
禁止把：
- 密钥
- 私钥
- 管理员口令
- 数据库 service key
- 敏感用户信息

写进前端或 GitHub 公共代码。

## 三、每次新功能完成后的回归检查

至少检查：

- 首页
- 导航
- KIT
- EVENT
- TORANHE
- BROADCAST
- ABOUT
- 手机端 390px
- 桌面端
- 主要链接
- Logo
- 底部文案
- 404
- Console 明显错误
- 旧入口

如果修改 EVENT：
额外执行 EVENT 自己的回归测试。

## 四、日常维护不等于乱改

Codex 不允许：

- 为了“优化”随意改品牌文案
- 未经要求重做整个首页
- 把稳定页面重构成新框架
- 因代码洁癖大规模重写
- 擅自删除历史内容
- 擅自改变产品名称
- 擅自合并 TORANHE 与 SAGI EVENT

维护原则：

发现问题 → 判断影响 → 最小修复 → 验证 → 提交。

## 五、维护报告格式

每次维护结束只需报告：

1. 发现的问题
2. 修复的问题
3. 修改文件
4. 手机端检查
5. 线上验证
6. commit
7. 仍需人工确认的事项

不要写大量无关技术过程。

## 六、长期维护重点

持续关注：

- 过期赛事内容
- 过期产品描述
- 导航一致性
- 手机适配
- 死链
- 页面加载速度
- 缓存
- 数据兼容
- GitHub 与线上版本差异
- SAGI 品牌一致性

核心原则：

**网站不是做完一次，而是长期保持正确。**

## 七、SAGI EVENT 用户反馈驱动的日常改进机制

SAGI EVENT 的维护不能只停留在修 bug 和改页面。

Codex 需要把真实用户反馈作为持续完善赛事管理能力的重要输入，并形成固定闭环：

**收集反馈 → 判断价值 → 分析影响 → 小范围实现 → 实际验证 → 回归测试 → 上线观察 → 再评估**

### 1. 先判断反馈是否值得做

收到“意见与建议”后，不允许看到建议就直接实现。

Codex 必须先分析：

- 这个问题是否来自真实赛事管理场景？
- 是个别用户习惯，还是多个赛事都会遇到的共性问题？
- 它是否能减少赛事管理员的操作步骤？
- 是否能降低出错概率？
- 是否能提高比赛当天的处理速度？
- 是否能让比分、积分、晋级、球员、纪律等记录更准确？
- 是否能让异常情况更容易处理？
- 是否能提高手机端使用效率？
- 是否能提高赛事信息的可追溯性与可信度？
- 是否符合“基础赛事管理永久免费，但要做到最专业”的产品方向？

### 2. 四个核心价值判断

每条建议至少从以下四个维度评估：

#### A. 是否更好地服务赛事
判断它是否真正帮助：
- 赛事组织者
- 赛事管理员
- 裁判 / 技术台
- 球队领队
- 现场工作人员
- 参赛球队

#### B. 是否提高 SAGI EVENT 的可用性
例如：
- 更少点击
- 更少重复录入
- 更清楚的页面结构
- 更好的手机端操作
- 更少误操作
- 更容易恢复错误
- 更符合真实比赛流程

#### C. 是否提高赛事管理水平
例如：
- 数据更准确
- 规则更严谨
- 流程更标准
- 责任更清楚
- 记录可追溯
- 赛后可复盘
- 异常情况有正式处理方式

#### D. 是否值得长期维护
避免加入：
- 只为一个人服务的特殊按钮
- 与赛事管理无关的装饰功能
- 会明显增加维护成本但价值很低的功能
- 会破坏现有稳定性的“炫技”功能
- 与 SAGI EVENT 核心定位冲突的功能

### 3. 反馈优先级

分析后将反馈分为：

- **P0｜影响比赛正确性**
  例如比分、积分、晋级、球员身份、纪律、比赛状态、数据丢失。

- **P1｜明显提高赛事管理效率**
  例如批量录入、排赛、名单打印、签到、快速纠错、场地调度。

- **P2｜提高使用体验**
  例如手机端操作、文案、入口位置、减少点击。

- **P3｜个性化 / 低频需求**
  先记录，不急于实现。

### 4. 不只看“用户说什么”，还要判断“用户为什么这么说”

Codex 必须尝试找到反馈背后的真实问题。

例如：

用户说：
“这里能不能再加一个按钮？”

不要立刻加按钮。

应该先判断：
- 是不是原来的入口太难找？
- 是不是操作流程太长？
- 是不是状态表达不清楚？
- 是不是现有功能其实已经存在但用户不知道？

优先解决根因，而不是无限增加按钮。

### 5. 每次改进必须有可验证目标

任何由反馈产生的改进，都必须说明：

- 原来的问题是什么
- 哪类赛事用户会遇到
- 为什么值得做
- 修改后具体改善什么
- 如何验证它真的更好

不能只写：
“优化体验”
“提升用户感受”

必须能够实际验证。

### 6. 改进后的验收问题

Codex 每完成一个反馈驱动改进，必须自问：

1. 赛事管理员现在是否更容易完成任务？
2. 是否减少了操作步骤或重复工作？
3. 是否降低了出错风险？
4. 是否提高了数据准确性？
5. 是否让异常比赛更好处理？
6. 是否让手机现场操作更快？
7. 是否增加了不必要复杂度？
8. 是否破坏已有赛事数据或旧流程？
9. 是否真的提高了 SAGI EVENT 管理赛事的水平？
10. 如果删除这个新功能，用户是否会明显失去价值？

如果第 9 项无法明确回答“是”，原则上不要为了功能数量而加入。

### 7. 反馈不能自动变成开发任务

用户反馈是输入，不是命令。

Codex 可以提出：
- 接受
- 合并到已有功能
- 延后
- 不采纳

但必须给出产品理由。

高风险规则变化、赛事结果含义变化、隐私/安全变化，必须交由产品负责人确认，不能自行决定。

### 8. 形成长期产品闭环

SAGI EVENT 的长期维护目标不是“功能越来越多”，而是：

- 办比赛更轻松
- 现场管理更稳定
- 数据更准确
- 流程更专业
- 出错后更容易恢复
- 新用户更容易上手
- 老用户越用越顺手

核心判断标准：

**这次改进有没有让 SAGI 更好地服务一场真实比赛？**

如果没有，就不应该仅仅为了“更新版本”而做。
