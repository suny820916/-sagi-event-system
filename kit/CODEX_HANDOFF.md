## 用户确认的工作方式
这是“原版球衣品牌替换 + 高清还原”，不是重新设计球衣。

必须严格遵守：
1. 原图决定版型、领口、袖口、肩线、侧拼、纹路、暗纹、线条位置、比例与数量。
2. 原图决定每一个配色，不能只换底色，不能擅自改领口、袖口、短裤或拼接。
3. 仅清理旧 LANTU / 原品牌 / 旧号码 / 旧徽章，并替换为 SAGI A+红点体系。
4. 胸前加入 `SAGI` 字样；Logo 比例必须自然，不遮挡原纹路。
5. 保留原面料褶皱、光影和纹理连续性；禁止模糊块、大色块、明显修补痕迹。
6. 用户要求商品图为高清、4K级观感，默认展示“背面球衣 + 正面球衣 + 短裤”三件套。
7. 每款流程：先发原图 → 放大主图看细节 → 做母版 → 用户确认 → 依据原图逐个做其他配色 → 用户确认 → 入库。
8. 用户明确说“不要自己创造”。任何重新设计都视为失败。
9. 配色必须逐个参考原图，不能通过一个母版简单换色来推导所有配色。
10. 未完成源图对照和视觉 QA 前，不得标记正式 published。

## Codex 立即执行任务
1. 先打开并读取 `kit/catalog-production.json`，以它为真实断点，不要从记忆推断。
2. 检查 `kit/` 当前目录树，确认 03–10 哪些实际图片资产/页面已经存在，哪些只是 catalog 状态。
3. 重点先完成 10 款：
   - 找到或整理用户确认的母版与八配色实际图像资产。
   - 统一命名并放入正式 assets 目录。
   - 不重新生成/重绘用户已确认的图。
   - 若资产缺失，不要冒充已完成；标记缺口并只处理能验证的内容。
   - 更新产品页/设计器入口。
   - 校验所有文件引用、图片尺寸、页面显示和移动端可见性。
4. 然后按 08 → 09 的顺序补齐已确认但 pending assets 的正式资产和页面。
5. 回头核查 04–07：用户在对话中已确认，但 catalog 尚未反映，需要根据现有资产真实性决定是否补登记。没有真实资产就不能直接改成 published。
6. 03 继续保持独立修复逻辑，不能因为其他款推进而误标完成。
7. 只有当真实图片资产、页面入口和 QA 都完成时，才允许改为 published。
