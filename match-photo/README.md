## 支付原则
- 网页 / 小程序 **不接支付接口**
- 不展示微信收款码
- 用户与 SAGI 通过微信单独完成付款
- 管理员确认到账后，点击“已收款 · 生成下载码”
- 下载码格式为人类易输入的 10 位码，例如 `ABCDE-23456`
- 用户只需要下载码，不需要再输入订单号
- 普通订单接口不会返回下载码；只有管理员接口能看到下载码

## 国内使用
生产环境不依赖网页内微信支付，也不依赖海外支付回调。

前端可以继续放在 SAGI KIT；照片服务建议使用在中国大陆访问稳定、支持持久对象存储的后端。正式比赛照片不能依赖临时磁盘。

需要的环境变量：
- `ADMIN_KEY`：管理员密钥
- `DATA_DIR`：持久数据目录（仅文件系统部署时）
- `ALLOWED_ORIGINS`：允许访问 API 的 SAGI 域名列表
- `PUBLIC_TITLE`：公开标题

## 摄影师端
SAGI KIT 新增 `kit/photo-upload.html`，摄影师与管理员彻底分权。

摄影师可以：
- 输入当天上传码
- 查看赛事列表
- 填写场次 / 球队
- 一次最多上传40张
- 自动生成水印预览
- 查看上传是否完成

摄影师不能：
- 查看订单
- 查看用户联系方式
- 查看或生成下载码
- 修改价格
- 创建赛事
- 使用管理员密钥

配置：
- `PHOTOGRAPHER_CODES` 支持多个上传码，用英文逗号分隔，例如：
  `PHOTO-A,PHOTO-B,PHOTO-C`
- 正式比赛前必须替换示例码 `PHOTO-1123`
- 摄影师码只保存在当前浏览器会话中，不写入订单数据

推荐现场流程：
1. SAGI 管理端提前创建赛事。
2. 每名摄影师拿到独立上传码。
3. 摄影师打开 SAGI KIT → MATCH PHOTO → 摄影师上传。
4. 每场结束按“场次 + 球队”上传一批。
5. 上传完成后，买图页自动出现水印预览。


## 正式服务器存储版
生产服务器建议设置：

```
STORAGE_ROOT=/srv/sagi-photo
MIN_FREE_GB=20
```

目录结构自动生成：

```
/srv/sagi-photo/
  system/
    db.json
  tmp/
  events/
    <event-id>/
      originals/
      previews/
```

规则：
- 高清原图只保存在 `originals`，没有公开静态地址。
- 水印预览存放在 `previews`。
- 每个赛事独立目录，方便迁移、归档和备份。
- 摄影师上传先进入临时目录，处理完成后临时文件自动删除，避免大量照片常驻 Node 内存。
- 上传前检查服务器磁盘空间；默认要求至少保留 20GB。
- 空间低于安全线时返回 507 并停止写入，不会继续把服务器硬盘写满。
- 管理端可调用 `/api/admin/storage` 查看服务器存储路径、总空间和剩余空间。
- `DATA_DIR` 仍兼容旧部署，但新部署统一使用 `STORAGE_ROOT`。

正式使用仍建议将整个 `STORAGE_ROOT` 做异盘或异地备份；同一块硬盘上的第二份副本不能替代真正备份。
